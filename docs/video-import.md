# Видео → инвестиционная идея → портфель

Проект следующего этапа. Автоматический импорт видео по ссылке пока не реализован:
текущий интерфейс сохраняет ссылку и разбирает предоставленный пользователем текст.

## Рекомендуемый путь

1. Пользователь вставляет ссылку либо загружает видеофайл.
2. Отдельный модуль получает медиа, автора, название и дату публикации.
3. Из доступных субтитров извлекаются текст и таймкоды. При отсутствии или плохом
   качестве субтитров распознаётся аудиодорожка.
4. Одновременно извлекаются кадры при смене сцен и через интервалы. OCR или модель
   с пониманием изображений читает тикеры, подписи, таблицы и проценты. Интервал
   выбирается по тестовым роликам; редкая выборка может пропустить короткую подпись.
5. Модель объединяет речь, подписи и кадры в тезисы с источниками и таймкодами.
6. Пользователь видит «Что предлагает автор», выбирает идеи и подтверждает свой
   горизонт и отношение к риску. Предпочтения автора не становятся пожеланиями
   пользователя автоматически.
7. Тикеры сопоставляются с доступными инструментами. Текущие данные и красные линии
   проверяются отдельно; оптимизатор составляет план.
8. Исходный материал, извлечённые тезисы и принятые решения сохраняются в контексте
   портфеля. Аналитический чат может объяснить происхождение каждого решения.

## Два назначения одного импорта

Создание начинается с выбора «Своя стратегия» или «Чужая идея». Видео — один из
форматов чужой идеи наряду со статьёй и текстом, а не отдельный вид портфеля.

Импорт можно запустить и из существующего портфеля через «Добавить идею».
Он получает `portfolio_id` и после распознавания передаёт материал в разбор идеи
именно этого портфеля. Агент учитывает уже купленные позиции, пожелания, ограничения,
прошлые обсуждения и ранее добавленные источники. Новый портфель при этом не создаётся.
Предлагается сравнение «текущий состав / вариант с идеей», а не отдельная стратегия
в отрыве от истории. Пользователь может принять план, уточнить его или оставить
материал в истории без изменений состава.

Контракт этого шага уже поддержан `/api/account/portfolios/{id}/chat`:
`intent=idea`, `source_kind=video|article|text`, `source_title`, `source_url`,
`article_text` (универсальный текст источника). Пока для видео передаются готовые
тезисы или расшифровка. Будущий обработчик видео должен заполнять этот же путь,
а не дублировать логику адаптации и подтверждения.

Долгая задача импорта привязана к назначению. Если во время распознавания профиль
изменился, предложение рассчитывается по актуальному состоянию портфеля. Применение
всё равно проверяет версию профиля; предыдущие подтверждения не переносятся на новый план.

## Почему нужны и речь, и кадры

В ролике автор может сказать «покупаю вот эти три компании», показав их названия
только на экране. ASR не восстановит этот список. Напротив, ролик с одним статичным
кадром и подробной речью можно обработать главным образом через расшифровку.
Субтитры ускоряют импорт, но не заменяют проверку тикеров, чисел и отрицаний.

Для прототипа: субтитры/ASR + кадры + существующая модель анализа текста.
Альтернатива: передача полученного видео целиком мультимодальному провайдеру.
Например, Gemini поддерживает видеофайлы и публичные YouTube URL. Это не означает,
что произвольная TikTok-ссылка может быть передана модели без получения медиа.

## Получение TikTok

Официальный Display API отдаёт метаданные и ссылки для встраивания; его документированный
Video Object не содержит универсального URL скачивания MP4 или расшифровки.
Метаданные и `video_description` нельзя выдавать за распознанную речь.

В MVP можно проверить адаптер `yt-dlp` для доступных публичных роликов. Работа
экстрактора зависит от текущей платформы, региона и доступности ролика; процент
успешного импорта нужно измерять на настоящих ссылках. Результат загрузки проверяется
по MIME, размеру, длительности и фактическому наличию аудио/видео. Если доступ
отсутствует, интерфейс предлагает «Загрузить видео», сохраняя уже введённую ссылку.
Для эксплуатации адаптер можно заменить специализированным поставщиком импорта
после проверки его покрытия и условий на тех же примерах.

## Компоненты в этом репозитории

- `backend/video_sources.py`: адаптеры ссылок и загрузок; результат — локальный медиафайл,
  нормализованный ID источника и метаданные. Проверка публичных адресов и каждого
  перенаправления; временные файлы и отдельная рабочая директория каждой задачи.
- `backend/transcription.py`: общий интерфейс ASR. Начальный локальный вариант —
  `faster-whisper`; заменяемый вариант — внешний ASR API. Результат — сегменты
  `{start_ms, end_ms, text}`; качество и ошибки распознавания проверяются отдельно.
- `backend/video_evidence.py`: извлечение кадров, чтение текста и объединение с речью.
- `backend/video_jobs.py`: устойчивые фоновые задачи. Для локального MVP — SQLite и
  отдельный worker-процесс; для нескольких работников — очередь с Redis и воркерами.
- `backend/video_ideas.py`: структурированный разбор тезисов, проверка инструментов,
  разделение позиции автора и решений пользователя. Готовый объект передаётся
  существующему разбору профиля только после выбора пользователя.

Потенциальные API следующего этапа:

```text
POST /api/video-imports                 {url, portfolio_id?} → 202 {job_id}
POST /api/video-imports/upload          файл → 202 {job_id}
GET  /api/video-imports/{job_id}         состояние / результат / ошибка
POST /api/video-imports/{job_id}/confirm выбранные тезисы → новый портфель / предложение для существующего
```

Состояния: `queued → fetching → transcribing → reading_frames → extracting → ready`.
Отдельные исходы: `needs_upload`, `needs_review`, `failed`, `cancelled`.
При перезапуске задача возобновляется или явно получает ошибку; она не должна
оставаться бесконечно «в работе». Есть таймауты, лимиты и ограниченные повторы.
Браузеру достаточно опроса по `job_id`; прогресс отображается словами, без
выдуманных процентов готовности или обещаний времени.

Кэширование по ID ролика и хэшу файла, а также версии обработчика/моделей позволяет
повторно использовать расшифровку, но не смешивать персональные диалоги портфелей.
Медиа обрабатываются с ограничением CPU, памяти, длительности и объёма; удаляются
по заданному сроку хранения. Ошибка скачивания не маскируется текстовой заглушкой.

## Структура результата

```json
{
  "source": {"url": "...", "author": "...", "published_at": null},
  "transcript": [{"start_ms": 12000, "end_ms": 18000, "text": "..."}],
  "ideas": [{
    "claim": "Автор предлагает увеличить долю нефтегаза",
    "instruments": [{"name": "...", "secid": null, "resolution": "needs_review"}],
    "action": "increase",
    "horizon": null,
    "suggested_weight": null,
    "evidence": [{"start_ms": 12000, "end_ms": 18000, "channel": "speech", "quote": "..."}],
    "uncertainties": ["Тикер не назван однозначно"]
  }]
}
```

Числа и инструменты не додумываются. Прошлая рекомендация автора не считается
актуальной котировкой. Утверждения из видео проверяются отдельно от их извлечения.
План не должен ослаблять красные линии пользователя, а контент ролика не должен
выполняться как инструкция системе. Неоднозначные места показываются на уточнение.

## Проверка перед обещанием «вставьте любую ссылку»

Набор реальных роликов: русский и английский; речь без субтитров; текст без речи;
быстро сменяющиеся тикеры; таблица долей; несколько спикеров; отрицания; числа;
неоднозначные названия; недоступная ссылка. Проверять отдельно успешность получения
ролика, качество извлечения фактов, связь с таймкодами и соответствие плана ограничениям.
Фактические задержки и стоимость измеряются на этом наборе.
