# Границы продуктового прототипа

Для текущей итерации продуктовые экраны проектируются с условием, что анализ видео
доступен. В интерфейсе пользователю предлагается ссылка или загрузка файла;
технические детали распознавания не входят в этот сценарий.

## Видео

`backend/video_prototype.py` — явная подстановка для проверки взаимодействий,
а не медиаобработчик. `/api/video/analyze` принимает ссылку или имя файла и возвращает
заранее заданный пример идеи с `mode=prototype`. Реальный видеофайл не скачивается,
не передаётся на сервер и не хранится; распознавание и чтение кадров здесь не выполняются.
Файловый выбор в браузере на этом этапе проверяет имя/размер для продуктового сценария.

Результаты помечаются `analysis_mode=prototype` в источнике. Их нельзя трактовать как
проверенные сведения о переданном ролике. При замене адаптера на настоящий обработчик
нужно подключить фактическую передачу файлов, фоновую обработку и таймкоды, сохранив
интерфейс источника. План такой обработки: [video-import.md](video-import.md).

## Агентное управление

`backend/management.py` работает только с локальными позициями в SQLite. Нет вызовов
брокерского API, открытия реального счёта или перемещения денег. Действие «Проверить
портфель» прогоняет квартал из загруженной истории и выполняет локальную ребалансировку,
если она проходит ограничения подтверждённого поручения. Фонового планировщика нет.

- Состояние ручного портфеля хранится отдельно от счёта агента.
- Сумма задаётся при создании счёта и не возникает повторно при переключении режимов.
- Пауза запрещает исполнение; возврат к ручному режиму сохраняет счёт агента.
- Агент использует копию подтверждённого поручения. Редактирование профиля не меняет её
  до явного подтверждения обновления.
- Изменение счёта/состава делает старое предложение из чата непригодным к применению.
- В журнал записываются только фактически выполненные локальные действия и их проверки.

API:

```text
PUT  /api/account/portfolios/{id}/management          mode, agent_id, amount_rub, revision
POST /api/account/portfolios/{id}/management/actions  pause | resume | review | approve_mandate, revision
```

## Каталог сообщества

`backend/community.py` содержит шесть примеров портфелей и три примера агентов.
Авторы — названия сценариев, не подтверждённые реальные пользователи. Отдельно
SQLite хранит публикации, которые пользователь явно создал через форму.

Публичный снимок состоит из профиля целей, ограничений и тематических инструментов.
Из пользовательского состояния не копируются переписка, источники, суммы, идентификаторы
счетов, история исполнения или произвольные подписи приватных правил и тем.
При использовании публикации создаётся независимое состояние в аккаунте получателя.

```text
GET  /api/community
GET  /api/community/{id}
POST /api/community/{id}/use
POST /api/community/publish
```

Это локальная модель взаимодействий. Аутентификация разных участников, модерация,
платежи, комиссии и реальное копирование брокерских сделок в неё не входят.
