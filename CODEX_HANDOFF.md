## Приложение

FastAPI + обычный HTML/CSS/JavaScript, без React и Tailwind. FastAPI раздаёт фронтенд.
SQLite хранит портфели и их историю. Данные бумаг — `data/universe.json`.
Архив содержит согласованные копии SQLite и текущую базу бумаг; окружение Python
нужно создать заново по `requirements.txt`.

Маршруты:

- `/` — подробный редактор: пожелания, пятиугольник профиля, красные линии,
  бумаги, тематический поиск, мандат, показатели, подтверждение сделок.
- `/v2` — три шага: пожелания → бумаги → итог.
- `/account` — портфели, общая сумма и количество стратегий, создание/редактирование.
- `/v2?portfolio=<id>` — сохранённый портфель, предпочтения, управление человеком
  или агентом, отдельный счёт агента, пауза/возобновление, журнал, позиции и план,
  распределение по отраслям, идеи, чат и публикация.
- `/community` — каталог портфелей сообщества, поиск и фильтры риска,
  подробности, взятие за основу и добавление идеи к существующему портфелю.

Общая нижняя навигация: «Портфель / Идеи / Аккаунт».

## Согласованное поведение

Каждый портфель имеет собственные предпочтения, ограничения, исходные материалы
и историю общения. В уже существующий портфель можно добавлять новости, текст,
статьи и видео. Анализ сопоставляет новую идею с текущим портфелем, показывает
сценарий до/после и предлагает изменения. Применение плана и совершение сделок
подтверждаются отдельно. Агент может рекомендовать не спешить с решением.

Создание: «Своя стратегия» или «Чужая идея». Источник чужой идеи: видео, статья,
текст. Для видео доступны ссылка и выбор файла. В данном продуктовом демо
содержание видео подставляется через `backend/video_prototype.py`; полноценное
автоматическое извлечение из произвольного ролика ещё не подключено. Пользователь
осознанно просил демонстрировать сценарий как доступную функцию и не выводить
технические оговорки об этом в интерфейс. Не обещать, что реальный конвейер
загрузки/распознавания видео уже реализован.

Управление агентом в личном портфеле сохраняется. Раздел агентов в публичном
каталоге удалён по последнему запросу. Серверные возможности управления агентами
остались. Публикация из интерфейса всегда создаёт карточку типа `portfolio`,
чтобы она была доступна в оставшемся каталоге, включая управляемые агентом портфели.

## Следующая цель: минимальное демо на российском хостинге

Пользователь хочет только минимально рабочую демонстрацию с собственным ключом
OpenRouter. Пользователь выбрал
Timeweb Cloud VPS в российском дата-центре, ориентировочно 2 vCPU / 2 ГБ RAM,
25–30 ГБ SSD/NVMe, Ubuntu 24.04 LTS, публичный IPv4, без GPU и панели управления.
Пользователь создаёт сервер; IP и ключ OpenRouter пока не предоставлял.
На Mac уже есть публичный ключ `~/.ssh/id_ed25519.pub`: предложено скопировать его
через `pbcopy < ~/.ssh/id_ed25519.pub` и добавить при создании сервера в Timeweb.
Для поля cloud-init подготовлен `deploy/cloud-init.yaml`: установка Docker,
Compose и rsync, создание папки проекта. Секреты и SSH-ключи в нём не задаются.

Для демо достаточно одного сервера, FastAPI + статический фронтенд, постоянного
файла SQLite, текущих демонстрационных данных, ссылки и пароля для просмотра.
Приложение сейчас использует общий локальный кабинет; многопользовательскую
авторизацию не считать реализованной. Публичную демоверсию стоит закрыть паролем.

OpenRouter уже подключён через OpenAI-совместимый API:

- `OPENROUTER_API_KEY` — секрет на сервере, не во фронтенде и не в Git;
- `OPENROUTER_BASE_URL`, `FAST_MODEL`, `SMART_MODEL` — настройки в `backend/config.py`;
- для настоящих вызовов нужен действующий ключ и выключенный `MOCK_LLM`;
- доступность OpenRouter и выбранной модели с конкретного российского IP
  не проверена. Не обещать её на основании названия хостинга; нужен реальный
  минимальный запрос с этого сервера. Условия моделей могут ограничивать регионы;
- сайт и база могут размещаться в РФ, но отправляемые OpenRouter запросы уходят
  внешнему сервису. Это не полностью изолированная российская обработка данных.

Подготовлены `Dockerfile`, `compose.yaml`, `compose.public.yaml`, `deploy/Caddyfile`,
`.env.deploy.example`, `.dockerignore`, инструкция `docs/deploy-demo.md`.
Базовый запуск: Caddy с паролем на loopback:8080 и доступ через SSH-туннель.
Публичный вариант: домен, HTTPS через Caddy, порты 80/443. FastAPI не публикует порт
на хост; пароль защищает весь интерфейс и API. Пароль в Caddy хранится как bcrypt-хеш,
секреты передаются на сервере через игнорируемый `.env.deploy`.
SQLite сохраняется в named volume `/state`; текущая локальная SQLite в образ не включена.
Новая база получает встроенные учебные примеры. Локальные портфели и чаты не копируются
на сервер автоматически; при необходимости согласовать отдельный перенос.

`scripts/serve_demo.py` проверяет ключ, базу бумаг и запись в SQLite перед запуском.
Без ключа запуск разрешён только при явном `MOCK_LLM=1`.
`scripts/demo_healthcheck.py` проверяет готовность без LLM-вызовов.
`python -m scripts.check_openrouter` делает маленький реальный запрос через structured
outputs приложения; запускать из контейнера на VPS после заполнения `.env.deploy`.

Проверено в отдельной временной копии с Python 3.13: 13 account + 9 management +
7 deploy checks, а также smoke API. Обе конфигурации прошли `docker compose config --quiet`.
Docker daemon на Mac не запущен: сборка образа, cloud-init на Ubuntu, Caddy/HTTPS,
сохранность Docker volume при пересоздании и реальный OpenRouter с IP сервера
ещё не проверялись. Backend, интерфейс и исходные данные не менялись.

дождаться cloud-init, перенести V2, заполнить секреты на сервере, выполнить проверку
OpenRouter и запустить демо по `docs/deploy-demo.md`. Затем проверить 401 без пароля,
вход с паролем, реальный ответ модели и сохранение портфеля после пересоздания контейнера.
